# 客户端语言与英文文档

[English](LOCALIZATION.en.md)

## 选择客户端语言

在“设置 → 外观 → 语言”选择“跟随系统”“简体中文”或“English”。默认跟随系统：中文系统语言（包括中文地区变体）使用简体中文，其他系统语言使用英语。手动选择后立即更新界面；选择“跟随系统”后恢复按系统语言显示。

语言选择保存在本机全局设置 `language_preference`，取值为 `system`、`chinese` 或 `english`。设置缺失或值无法识别时使用 `system`。切换工作区或同步账户不改变该选择。语言设置不参与同步，也不随工作区备份迁移。保存失败时保留原选择，并提供重试入口。

翻译覆盖导航、任务与计划编辑、日历、专注、统计、登录、设置、私密任务箱及应用生成的提示。日期、星期和紧凑时长按当前语言显示。任务标题、备注、项目名、标签、已保存设备名和用户修改的策略名保留原文。内置专注策略仅在 ID 与原始名称均匹配时翻译显示名，存储和同步内容不变。

Android 任务提醒、专注通知、通知渠道名称、守护提示及文件操作错误使用相同选择。原生层保存语言副本，使 Flutter 未运行时的提醒仍能选择语言；应用启动、恢复前台或改变语言时更新该副本。原生更新失败不阻止本地工作区使用，下次恢复前台时重试。系统文件选择器、权限界面和系统设置页面由 Android 控制，其语言由系统决定。

此前生成并保存在界面状态中的错误或通知提示保留生成时的语言；重新执行相关操作后使用新语言生成提示。

## 维护界面翻译

`client/lib/core/localization/english.dart` 汇总中文源文案到英文的映射；系统日历等功能可通过其引入的独立目录（如 `system_calendar_english.dart`）维护译文。界面使用 `context.tr(...)`，通过 Flutter 本地化依赖在语言改变时重建；控制器、模型显示名和错误消息使用 `tr(...)`。新增文案须使用静态中文键，并同时加入英文映射。英语缺少键时返回中文源文案，自动检查应在合并前发现缺项。

动态数据通过 `args` 传入 `{name}` 占位符。中英文保留相同占位符；不得将用户输入作为翻译键，也不得对已替换参数再次替换。Android 文案位于 `res/values/strings.xml` 和 `res/values-zh/strings.xml`，资源名称与格式参数须一致。

在 `client` 目录运行：

```sh
flutter analyze
flutter test test/localization_test.dart
flutter test
flutter build apk --debug
```

本地化测试检查目录覆盖、占位符、日期格式、语言保存、失败处理及页面切换。原有 GUI 回归测试显式使用中文；英语测试独立设置语言。新增页面须检查英文长文及较大字体布局。自动测试和调试包编译不能代替 Android 真机上的通知、系统语言切换、权限和无障碍验收。

## 公开文档范围

公开 Markdown 文档在原目录提供 `.en.md` 英文副本，通过文件开头的链接切换语言。接口参考提供 `api/openapi.en.yaml`，GitHub 缺陷与功能表单提供 `.en.yml` 英文副本。许可正文、第三方原始许可、版权署名、命令、配置键和协议字段保持原样；翻译不改变授权、贡献规则或历史验证结论。

`scripts/prepare_public_source.py` 的允许列表决定公开范围。英文文件沿用对应中文文档的公开权限，不会使内部报告或部署记录自动进入公开源码。中文原稿更新时应同步核对英文版本。

Android 系统日历连接的权限、数据流和冲突处理见[系统日历同步](SYSTEM_CALENDAR.md)。
