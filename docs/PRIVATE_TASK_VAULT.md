# 本地私密任务箱

[English](PRIVATE_TASK_VAULT.en.md)

私密任务箱使用独立密码保存当前工作区的私密任务、分类、标签、计划和专注记录。
这些记录保存在本机密文表中，不进入普通任务表、普通同步队列或服务器接口。
私密箱无需同步账户或网络；每个工作区分别设置密码。

## 设置密码与锁定

从任务页右上角的锁图标，或“设置 → 数据备份与工作区 → 私密任务箱”进入。
首次设置需要两次输入相同密码，长度为 8 至 1024 个字符。
设置成功后才能新建或转入私密任务。密码与同步账户密码无关。

私密箱在进程启动时保持锁定。以下操作会立即清除界面中的私密内容和解锁状态：

- 点击私密箱右上角的锁图标。
- 应用离开前台，包括打开系统文件选择器或进入其他应用。
- 切换工作区。
- 离开私密箱页面。

重新锁定会关闭私密编辑器和分类菜单，丢弃未保存的输入。
普通任务、搜索、项目与标签筛选、今日、日历、专注选择器和统计始终使用普通数据，
不读取私密箱中的正文与分类，即使私密箱当前已解锁。
私密任务的安排时间和专注记录在私密箱内查看。

密码错误或密文认证失败时，私密箱保持锁定，不删除原密文。
重试等待从 2 秒开始，每次翻倍，最长 256 秒；失败次数和下次可重试时间保存在本机，
重启应用不会立即清除等待时间。界面不会区分“密码错误”和“密文损坏”。

## 私密任务、计划与专注

在私密箱内可以新建、编辑、完成和删除任务，设置优先级、备注、标签、截止时间、
预计用时与私密分类。任务按优先级排列，同级按内部顺序排列。
删除任务时一并删除其专属计划、专注和提醒等关联记录；仍在专注中的任务不能删除或移出。

“安排时间”使用本地时间，输入格式为 `yyyy-MM-dd HH:mm`，结束时间必须晚于开始时间。
点击已有计划可以修改开始和结束时间。私密计划保存在密文中，不在普通日历中显示，
当前不生成任务到期或计划开始的系统提醒。

私密箱提供普通模式专注，默认 25 分钟，可设置为 1 至 1440 分钟。
同一时刻只能开始一个普通或私密专注。私密专注不使用普通任务的策略选择器和白名单，
当前不提供暂停、守护模式或严格模式选项。

重新锁定后，已开始的私密专注继续按结束时间计时。
Android 服务、通知、锁屏和恢复数据只使用“私密任务”等通用名称。
查看任务正文或提前结束需要先解锁原工作区的私密箱。
计时完成时，锁定状态下只结束通用计时；下次解锁时再将完成结果写入密文。
系统计时通知更新失败时，界面保留提示并提供“重试通知”；已保存的私密记录不会转成普通记录。

本机计时控制标记不进入备份。复制工作区或恢复备份不会获得源设备的专注控制权。
恢复内容中的进行中专注会在首次解锁时标记为中断，不自动启动新设备上的计时服务。

## 普通任务与私密任务之间的转换

普通任务的“更多 → 转入私密任务箱”，或私密箱中的“转入本地任务”，可以迁移普通任务。
当前只允许原始本地工作区 `__local__` 中从未尝试同步的任务：

- 任务及专属关联记录的服务器版本和游标必须为 0。
- 关联同步修改必须从未被同步器读取为发送批次，且没有发送尝试或拒绝记录。
- 任务或专属计划不能有系统日历导入、关联或尝试写出的曝光记录；解绑日历或删除计划不清除此限制。
- 任务不能仍在专注中，也不能与其他普通任务共享需要一并迁移的专属记录。
- 同步工作区、复制的工作区和恢复的工作区均不能直接转入普通任务。

迁移会在同一 SQLite 事务中更新私密密文，移除任务及专属关联记录，
并删除这些实体的全部待发送、已拒绝和已被替代的同步修改。
正文或队列在提交前发生变化，或任一写入失败时，事务回滚，原普通数据和原私密密文保留。
普通项目、标签和专注策略等共享元数据会复制到密文内，原共享记录继续保留在普通工作区。

转入不会删除历史备份、文件系统快照或应用此前已产生的外部副本。
对于曾上传或尝试上传的任务，服务器历史和其他设备也可能保留原正文，因此当前拒绝直接转入。
系统日历及其服务商也可能保留已经交换的日程；客户端不能通过转入私密箱收回这些副本。
日历同步在尝试交换内容前保存本机曝光标记；写入结果无法确认或操作失败时也不清除标记。
转入前和提交事务内均检查该标记，
避免同步与加密迁移并发时把已经对外交换的内容当作从未分享。连接规则见[系统日历同步](SYSTEM_CALENDAR.md)。

在私密任务下选择“移出私密箱”，并确认允许普通存储后，任务与关联记录会写回普通工作区。
同步工作区中的移出记录可以进入同步队列。写回和私密密文更新在同一事务中完成；
标识冲突或写入失败时保留原私密记录。转换完成后，客户端重新加载普通列表并更新系统任务提醒。

## 密文备份与密码修改

“私密任务箱 → 密文备份”可以导出独立的 `pactick-private-vault.json` 文件。
文件包含格式版本、密码派生参数、随机盐、密文及认证标签，
不包含密码、明文正文或解密密钥。最大文件大小为 50 MiB。

恢复独立私密备份时，先选择文件并输入导出时的密码。
客户端完成格式、认证标签和内容关联校验后，才创建新的离线工作区。
原工作区保留，恢复的私密箱保持锁定；从“设置 → 数据备份与工作区 → 打开保留的工作区”进入恢复工作区后再次解锁。
新格式不支持、密文损坏或密码错误时，不创建恢复工作区。
新设备仅需备份文件和原密码，不依赖源设备的系统安全存储。

完整本地备份使用 `pactick-workspace` v2 格式，将私密箱作为 `private_vault` 密文字段携带，
不将其解密成普通文档。旧版 v1 普通备份仍可恢复。
复制工作区也按密文复制私密箱，并保留原工作区。
完整备份恢复时仅校验私密字段的格式；私密认证在解锁时执行。
如需在创建工作区前验证私密内容，应使用独立私密备份恢复入口。

修改密码需要先解锁并验证旧密码。客户端生成新随机盐，使用新密码重新加密整个私密箱，
再原子替换密文。写入失败时，原密码和原数据仍然可用。
旧备份继续使用导出时的密码，修改当前密码不会改写已导出的文件。
当前不提供绕过原密码读取内容的重置方式；忘记密码后无法恢复内容。

## 存储与内容保护

实现使用维护中的 [cryptography](https://pub.dev/packages/cryptography) Dart 包，参数如下：

| 项目 | 当前参数 |
| --- | --- |
| 密码派生 | PBKDF2-HMAC-SHA256，600000 次，256 位输出 |
| 随机盐 | 每次设置或修改密码生成 32 字节随机盐 |
| 正文加密 | AES-256-GCM |
| 随机 nonce | 每次保存生成新的 12 字节 nonce |
| 认证标签 | 16 字节，同时认证格式、算法参数和通用计时元数据 |
| 明文内容容量 | 单箱最多 35 MiB，最多 100000 个实体；密文备份最多 50 MiB |

SQLite schema v3 新增 `private_vaults` 表，仅保存工作区标识、密文和重试元数据。
普通 `documents` 与 `pending_operations` 表不读取或保存私密箱正文。
盐、密文大小、失败次数及通用计时的随机会话标识和起止时间不属于隐藏元数据。
本机专注控制标记绑定工作区、会话和完整密文的 SHA-256 摘要，
不随备份和工作区复制迁移；未经认证且没有匹配本机标记的头部不能启动计时。

Android 在进入私密页面前设置 `FLAG_SECURE`，用于阻止系统截图和最近任务预览保留该页面。
设置失败时不打开私密页面。其他平台未提供系统截图保护。
锁定会释放已解密内容并销毁应用持有的密钥字节；Dart 托管内存中的历史字符串不能保证物理清零。
此功能不保护已经解锁的应用进程，也不清除操作系统备份、用户手动复制的内容或转入前的旧副本。

## 维护与验证

主要实现位于：

- `client/lib/core/state/private_vault_controller.dart`：唯一解锁访问入口、锁定、转换和私密专注。
- `client/lib/data/local/private_vault_crypto.dart`：版本化密文信封、标准密码派生与认证加密。
- `client/lib/data/local/private_vault_storage.dart` 与 `local_database.dart`：密文存储和事务转换。
- `client/lib/features/tasks/pages/private_vault_page.dart`：私密内容界面与锁定时输入和菜单清理。
- `client/test/private_vault_test.dart`：真实 SQLite、内存存储、加密备份、同步隔离、故障回滚和界面锁定测试。

在 `client` 目录运行 `flutter test test/private_vault_test.dart`。
测试覆盖存储隔离、数据库明文检查、转入转出、密码修改失败、损坏备份、跨存储恢复、
旧格式兼容、本机计时控制权和锁定期间的异步竞争。
桌面单元与界面测试不能证明 Android 实机上的后台计时、截图限制、通知或厂商进程管理行为；
这些行为仍需单独进行设备验收。
