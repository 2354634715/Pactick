## 真实备份与隔离恢复

Debian WSL 的 Docker 环境使用独立 Compose 项目、临时卷及合成用户、设备和任务，实际执行当前部署脚本：

1. 应用当前三个数据库迁移，创建合成业务记录。
2. 执行每日备份和迁移前备份，核对真实 `pg_dump`、目录清单、SHA-256 和成功标记。
3. 运行原始 `restore-check.sh`，恢复迁移账本并确认源库数据仍在。
4. 损坏的 dump 在校验阶段被拒绝。
5. 再次在独立、无网络的数据库容器恢复，核对用户、设备、任务与迁移记录数量为 `1/1/1/3`，任务正文一致。

以上检查全部通过。本次新建的容器、卷、网络和临时配置目录均已清理。该结果验证真实数据库备份及隔离恢复，不代表已完成生产数据恢复、新主机应用安装、定时任务或完整升级验收。
