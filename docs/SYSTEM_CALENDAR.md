# Android 系统日历同步

[English](SYSTEM_CALENDAR.en.md)

系统日历连接用于在 Android 日历提供程序与当前工作区的普通计划时段之间交换日程。连接默认关闭，不要求登录 Pactick 账户；私密任务箱不参与此连接。

## 连接前确认

每个本机工作区选择一个已有、可见且允许读取的系统日历。客户端不创建系统日历账户，也不替日历账户登录或配置其网络同步。

连接后，系统日历事件的标题和时间会成为客户端普通计划。当前工作区已启用账户同步时，这些计划会按原有流程上传到所配置的 Pactick 服务器。客户端写入的系统事件也可能由该日历所属账户同步到其服务商。选择连接前，应确认这两种数据流均符合使用要求。

读取系统日历需要 Android `READ_CALENDAR` 权限，写入或删除系统事件需要 `WRITE_CALENDAR` 权限及所选日历的写入权限。具体事件还受组织者、与会者权限和系统提供程序限制，可写日历中的事件也可能只读。只有用户主动连接或申请权限时才弹出系统授权界面；拒绝权限不影响本地任务、计划、专注或备份。

## 建立与停止连接

1. 打开“设置 → 系统日历”，点击“选择系统日历”。客户端在缺少读取权限时主动申请系统授权。
2. 选择已有日历。列表显示日历名称、账户显示信息以及是否可写；只显示系统中可见且允许读取的日历。
3. 阅读数据流说明，确认“启用同步”。所选日历可写但尚未授权写入时，客户端会申请写入权限；读取仍获准而写入未获准时，可保持只读连接。启用成功后立即执行首次同步，建立事件与普通计划的关联。
4. 按需选择未来 30、90、180 或 365 天的同步范围。在客户端或系统日历编辑已关联记录后，前台连续变更合并并等待 2 秒再交换；恢复前台时重新检查，也可点击“立即同步日历”。
5. 关闭“系统日历同步”开关后停止后续读取和写入；已提交给系统提供程序的单条原子操作仍可能完成，已导入的计划与已创建的系统事件保留。

更换日历不会批量删除旧日历的事件。新日历按新连接范围处理当前普通计划，可能创建对应的新系统事件；旧日历中的副本不会自动移除。不同工作区的连接设置和关联分别保存；切换工作区后只处理当前工作区。恢复或复制工作区不继承原设备的日历连接，需重新选择日历并确认连接；系统权限按 Android 当前授权状态检查，仅在缺少权限时再申请。

应用不为日历连接启动持续后台服务。应用关闭或不在前台时，不保证即时交换变更；再次打开或恢复前台后检查。系统日历本身何时与其服务商交换数据，由 Android、日历账户和系统设置决定。

## 同步内容与范围

| 内容 | 行为 |
| --- | --- |
| 普通计划的标题、开始与结束时间、时区 | 参与双向更新；系统新事件导入为独立普通计划，不创建任务或修改任务正文 |
| 全天事件 | 通过日期对应的起止区间表示，保留不包含结束日期的语义；客户端仍以计划时段表示，不新增独立全天提醒 |
| 重复事件 | 按窗口内的每次发生建立关联；含 `RRULE` 的重复事件通过单次异常记录修改或取消，不改写整个系列；仅由 `RDATE` 列举且尚无独立异常记录的重复实例当前只读 |
| 描述、地点、提醒、与会者 | 不导入到计划，也不因同步标题与时间而覆盖系统原值 |
| 任务截止时间与专注记录 | 不作为系统事件导出，完成任务不等于删除系统事件 |
| 私密任务、私密计划和私密专注 | 不读取、不导入、不导出，也不向系统日历发送标题或时间 |

默认发现窗口为过去 30 天至未来 180 天，包含今天及未来范围最后一天的完整当地日期；过去范围固定为 30 天，未来范围可选 30、90、180 或 365 天。新关联只处理与窗口相交的普通计划和系统事件。窗口之外没有出现在扫描结果中，不表示事件已经删除；已关联事件须通过其标识核对。

客户端普通计划要求结束时间晚于开始时间，跨度不超过七天（168 小时）。标题超过 500 个 UTF-16 码元或时间范围无法表示的系统事件跳过并计数，不截断其时间，也不删除系统原事件。已经关联的系统事件变成无法表示的格式时，保留两侧并列出不支持的冲突，不自动覆盖客户端。

有时刻的系统事件使用兼容的 IANA 时区标识；原时区缺失时采用设备时区，不可识别或固定偏移时区以 UTC 表示同一瞬间，不因此改变起止时刻。全天日期按设备当地日期表示。仅编辑标题等未改变时区语义的内容时，保留提供程序原有的起止时区元数据。

配置接口要求过去天数、未来天数与今天合计不超过 400 个当地日期；当前界面最大范围为 396 个当地日期。原生读取另设 402 × 24 小时的硬限制，以容纳当地日期窗口与夏令时变化。单次读取最多处理 10000 条事件。超过上限或读取未完整完成时报告失败，不能将部分结果作为完整快照继续处理删除。

## 冲突和删除

每次成功交换后保存已确认内容，下一次将两侧当前内容分别与该内容比较。用户编辑的标题和其他文字保持原文，不随客户端语言改变。系统空标题在客户端以稳定的“—”表示；仅修改时间或切换语言不会把占位写回系统标题。

| 检查结果 | 处理 |
| --- | --- |
| 仅系统事件变化 | 更新已关联的普通计划 |
| 仅客户端计划变化 | 有写入权限时更新已关联系统事件；只读连接不覆盖系统事件 |
| 两侧内容相同 | 确认当前内容，不重复创建日程 |
| 两侧分别改成不同内容 | 保留两侧，列出冲突，等待选择 |
| 任一侧删除或取消 | 列出冲突，等待选择；不自动级联删除 |
| 两侧均已删除或取消 | 清理该关联，不重新创建记录 |

已关联的全天事件在客户端发生相对上次确认内容的时区变化时，也须通过双侧变更冲突确认，不自动改成有时刻事件。全天属性只保存在本机关联中，普通计划的云端正文没有独立全天字段，不保证多设备、多时区下的全天表示完全一致。

“保留客户端版本”将客户端当前计划作为结果：系统事件缺失时重新创建；客户端计划已经删除时删除对应系统事件。“保留系统版本”将系统当前事件作为结果：客户端计划缺失时重新导入；系统事件已经删除时移除对应普通计划。处理计划不会删除关联任务或历史专注记录。

选择冲突处理后，客户端会重新读取两侧内容；原冲突标识不再匹配时，不将旧选择应用到新内容。写入前还会核对所选日历与事件版本。无写入权限时不能选择需要修改系统事件的结果；读取失败、权限撤销、日历不存在或日历标识变化时停止交换，不把这些情况视为事件批量删除。失败后保留已有计划和关联，处理原因后重试。本机数据库与系统日历不是同一个事务：一次同步中已完成的单条更新可能已经保存；重试依据关联和幂等标记继续，不表示整次同步会回滚。

## 私密任务与外部副本

已经导入、关联或尝试写出到系统日历的普通任务或专属计划，会留下本机曝光历史；此类任务不能直接转入私密任务箱。解绑、关闭连接或删除计划不清除这项历史。曝光标记在尝试交换前保存，即使写入结果无法确认或操作失败也保留。系统日历及其服务商可能仍保留原日程，转入私密箱不能收回外部副本。迁移条件与事务检查见[私密任务箱](PRIVATE_TASK_VAULT.md#普通任务与私密任务之间的转换)。

## 本机存储与维护

其他 Pactick 工作区写入并带有其关联标记的系统事件不会自动导入当前工作区，以免混合账户数据。

连接设置、事件标识、已确认内容和幂等标记属于本机关联状态，不进入普通同步正文，也不随工作区备份或复制迁移。这些设置使用工作区内的 `system_calendar_sync_v1`；本机安装标识为 `system_calendar_installation_v1`，曝光历史为 `system_calendar_exposed_v1`。普通计划正文继续使用现有 `plan_block` 契约；日历关联不新增云端事件字段。现有字段约束见[同步实体字段契约](ENTITY_SCHEMAS.md#plan_block)。

系统日历与事件标识由本机日历提供程序分配。未带 Pactick 幂等标记的外部事件不能依靠这些标识在不同设备间可靠匹配；同一 Pactick 账户在多台设备连接同一日历，可能产生重复普通计划或系统事件副本。建议同一账户对同一系统日历只在一台设备启用连接；迁移设备或清除系统日历数据后重新配置。Pactick 标记有助于识别同一导出计划，但第三方提供程序可能丢弃标记，不保证跨设备或跨提供程序精确去重。

实现应按工作区显式读取与写入本机文档，防止账号或工作区切换后的晚到结果写入新工作区。新建系统事件采用稳定幂等标记，避免系统写入成功、客户端确认保存失败后再次插入。原生层通过 Android 日历提供程序读写，并在更新前检查原值，不以最后一次写入盲目覆盖另一侧变更。

界面和原生错误提示须同时提供中文与英语，维护要求见[语言支持](LOCALIZATION.md)。日程标题、日历名称和日历账户显示信息按系统或用户输入显示，不作为翻译键。

## 验证范围

同步逻辑测试应覆盖首次连接、双向更新、只读、冲突、显式删除处理、窗口外事件、权限失败、失败重试、工作区切换和私密隔离。Android 真机还须分别检查权限拒绝与撤销、系统日历编辑、重复异常、全天与夏令时、账户日历的同步时机，以及厂商日历提供程序差异。

单元测试、界面测试和 APK 编译不证明上述真机行为已通过。验证结果应注明实际设备、权限与日历账户类型；不得将本机提供程序读写成功写成日历服务商的网络同步已经完成。
