# Pactick 源码公开与本地优先转型计划

> 编写日期：2026-09-29  
> 状态：代码与部署工具已实施，本地自动检查及 debug APK 构建通过；正式公开前仍须完成许可审阅、正式签名和真机/服务器验收  
> 适用基线：当前 Flutter Android 客户端、Go 服务端及 PostgreSQL 单机部署

## 一、转型目标

将项目转为允许个人和办公使用的社区项目。许可禁止利用软件本身商业获利，并要求对外提供衍生版本时共享对应源码。

项目所有者已选择“源码公开 / Source Available”定位。许可保留商业用途限制，因此不得将项目标注为符合 OSI 定义的开源软件。参见 [开源定义](https://opensource.org/osd)。

首个公开版本的目标：

- 无需账号即可使用任务、日历、专注和统计，并支持离线备份、恢复数据。
- 用户可自行部署 Go＋PostgreSQL 服务端，并在客户端选择连接。
- 维护者不提供公共云同步服务；现有服务器在个人数据迁移验证完成前保留。
- 公开客户端、服务端和部署源码，同时发布正式签名的 Android APK。
- 维护者按可投入时间处理反馈和贡献，不承诺固定更新频率或响应时间。

制定本计划时，项目仅由所有者本人使用，尚未收款，因此不需要迁移付费权益或安排外部用户过渡。项目所有者已确认有权自行授权；第三方依赖和素材仍须单独核查。

本计划最初依据源码与文档的只读检查制定，相关改造已实施。实际交付和验证结果见 [实施记录](TRANSITION_STATUS.md)。下文的现状描述以制定计划时的基线为准，不代表后续版本状态。

## 二、第一阶段：许可与公开源码

### 1. 制定项目许可

采用项目专用的源码可见许可。发布前须形成完整的许可草案、使用示例和第三方兼容性清单，并完成审阅确认。仅在 README 中注明“禁止商用”不满足此要求。

许可须明确以下场景的使用和分发条件：

| 场景 | 计划允许范围 |
| --- | --- |
| 个人学习、生活管理、研究、自部署 | 允许 |
| 公司内部办公、个人管理有收入的工作 | 允许 |
| 私人修改、自用修改 | 允许，无需公开 |
| 免费分发原版或修改版 | 允许，保留许可及署名，提供对应源码 |
| 对外提供修改后的免费网络服务 | 允许，提供实际运行版本的对应源码 |
| 售卖软件、收费托管、广告变现、纳入商业产品 | 禁止 |

“对应源码”包括项目修改及构建所需文件，沿用相同许可；不包括用户数据、部署密钥或无关的独立项目。用户填写的任务和笔记不受软件源码共享要求约束。

提供许可正文、中文说明和场景 FAQ，说明版权、专利、署名、衍生版本、免责和违约处理条款。第三方组件继续适用各自的许可，不得统一改标为项目许可。软件代码不直接采用 CC BY-NC-SA；Creative Commons 官方也不建议将其许可用于软件。参见 [CC 官方说明](https://creativecommons.org/faq/#can-i-apply-a-creative-commons-license-to-software)。

本节记录许可设计目标，具体条款以正式许可正文为准。许可审阅和依赖兼容性检查的完成情况须另行确认。

### 2. 准备公开源码目录

制定计划时的检查未发现可识别的 Git 仓库，因此计划从审阅后的源码快照建立新仓库。

- 保留源代码、测试、迁移、依赖锁文件、通用部署模板和文档。
- 排除缓存、日志、数据库备份、构建产物、历史发布压缩包、审计暂存目录、本机配置和签名材料。
- 将实际服务器地址、登录入口和个人背景从公开文档中移出，部署示例改为通用占位值。
- 扫描待发布文件中的凭据及敏感数据；若发现真实凭据曾公开或进入发布物，先轮换。
- 核对 Go、Flutter、Android 依赖及素材的来源、许可和必要声明，生成第三方声明清单。

原商业化规格保留为私人历史资料，不再用于当前实施路线图。公开规划移除试用、支付、激活和商业运营任务。制定计划时未发现已实现的付费模块，因此不需要为本次转型新增或拆除授权系统。

完成条件：发布目录可独立构建，公开文件清单和许可范围明确，不含私人运维资料或未处理的许可冲突。

## 三、第二阶段：完成本地使用与数据迁移

### 1. 解除本地功能对登录的依赖

复用现有 SQLite 和本地工作区能力：

- 首次启动直接进入本地工作区，登录移入“同步设置”。
- 断网、登录过期、服务器故障和同步协议不兼容，只影响同步。
- 本地查看、编辑、专注、统计和导出始终可用。
- 退出账号保留本地数据；删除本地数据必须是独立、明确的操作。
- 本地模式默认不请求维护者的服务器，不自动上传数据。

### 2. 实现本地备份和恢复

制定计划时，导出入口尚未接入实现；该项须在公开发布前完成。

- 新增带格式版本的本地备份，包含业务数据、本地设置和未同步修改，排除密码、令牌及签名材料。
- 导出不依赖网络；导入先校验格式和引用关系，再以事务写入。
- 首版导入恢复到新的本地工作区，不自动合并或覆盖已有工作区。
- 跨服务器恢复时保留业务内容，重新生成目标服务器的同步操作，不复用旧游标和凭据。
- 接入已有的服务端账户导出、删除接口，并分别说明其对服务器数据和本机副本的影响。

### 3. 保护现有个人数据

先备份现有数据库和客户端数据，再提供“复制为本地工作区”的迁移操作。迁移须保留原工作区，失败时可回退；未经用户选择，不得向新服务器上传数据。

2026-09-30 命名决策：产品尚未发布，Android 包名统一为 `com.example.pactick`，数据库与备份标识同步采用 Pactick。此次新安装使用独立数据空间；发行后的升级须保持新包名与正式签名连续性。

完成条件：无网络时，首次启动、创建任务、完成专注、导出和重新导入均可执行；旧数据迁移前后内容一致。

## 四、第三阶段：自部署、发行与社区维护

### 1. 将同步改为可选能力

- 设置页新增运行时服务器地址，不再要求用户重新编译 APK。
- 正式连接使用 HTTPS；本地开发保留显式的调试配置。
- 本地数据、令牌、设备登记和同步游标按“规范化服务器地址＋用户 ID”隔离。
- 切换服务器时先停止旧同步任务，禁止将旧令牌或未完成请求发送到新服务器。
- 首次连接默认使用独立的云端工作区；上传现有本地数据必须由用户明确选择。
- 通用部署文档覆盖启动、首次建号、关闭注册、升级、备份和恢复。

保留现有 `/v1` 业务 API 和同步契约；本次改造主要新增客户端服务器配置、工作区身份及备份格式。已发布的数据库迁移保持原样，必要变更通过新增迁移完成。

### 2. 调整更新与发布方式

首次发布使用 GitHub 仓库及 Releases，暂不计划上架应用商店。

- 移除同步服务器对整个客户端的强制更新限制；版本不兼容时暂停同步，保留本地功能。
- 首版通过“关于”页打开官方 Releases 查看更新，不增加自动后台检查服务。
- 发布源码标签、签名 APK、SHA-256、签名证书指纹、变更说明和构建说明。
- 签名密钥由维护者私下保管并备份；普通贡献者和 PR 验证无需接触密钥。
- 说明社区自行签名版本与官方 APK 的区别；文档不得将尚未实现的下载包自动校验写为已有功能。

### 3. 建立贡献与维护流程

- README 以“下载安装、本地使用、自部署、许可限制”为主线，截图使用演示数据。
- 提供贡献指南、问题模板、安全问题私下报告入口、第三方声明和变更记录。
- 贡献者保留自身版权，提交贡献需确认有权按项目许可提供。
- CI 执行 Go 与 Flutter 检查，并验证干净环境构建；签名发布独立于 PR 流程。
- 按“数据丢失与安全问题 → 核心功能缺陷 → 易用性 → 新功能”的顺序维护。
- 首版仅支持 Android；Windows、Linux、iOS、Web 和新增商业功能不在此次发行范围内。

完成条件：使用者仅依靠公开仓库即可构建客户端、部署服务器并完成同步，无需访问维护者的服务器或私人文件。

## 五、第四阶段：验收与首次发布

以下验收全部通过后，再公开仓库并发布首个预览版本：

| 验收项 | 必须通过的场景 |
| --- | --- |
| 本地使用 | 首次启动无账号、断网重启、创建与编辑任务、专注结束、统计正常 |
| 会话失效 | 令牌过期、账号撤销、服务器不可达时仍可使用和导出本地数据 |
| 数据隔离 | 两台服务器出现相同用户 ID 时，数据、凭据、队列和游标互不混用 |
| 数据迁移 | 旧版数据和未同步修改完整保留，失败回滚有效 |
| 备份恢复 | 导出后可恢复；损坏文件、不支持的格式不会破坏现有数据 |
| 同步 | 两台设备离线修改后恢复同步，冲突和删除行为符合现有契约 |
| 更新 | 更新提示和服务端版本要求不能封锁本地工作区 |
| 构建发布 | `go test ./...`、`go vet ./...`、`flutter analyze`、`flutter test` 通过；正式 APK 在真机验证 |
| 发布内容 | 无凭据和个人数据，第三方声明完整，APK 能关联到准确源码版本 |

各阶段按以下顺序执行：许可与公开目录 → 本地模式与迁移 → 可选同步与发布流程 → 验收及公开发布。

现有服务器须在个人数据备份、恢复和本地迁移全部验证后再安排停用。首次发布以可用的预览版为目标，不适用原商业化文档中“1.0 付费正式版”的发行条件。
