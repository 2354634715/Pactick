# 计划时段编辑与定时提醒

[English](TASK_SCHEDULING_AND_REMINDERS.en.md)

## 修改任务安排

在日历中打开一个计划时段，选择“编辑计划时段”；也可在任务详情的“计划时段”列表中选择对应记录。编辑器可修改日期、开始时间、时长和关联任务。取消关联后必须填写独立的日程标题。

保存修改会沿用原计划 ID，更新对应的同步文档，不创建重复时段。任务的截止时间、任务内容和实际专注记录单独保存；修改计划不会重算历史专注时长。“安排时间”仍用于新增时段，同一任务可有多个安排。

选择“删除时段”并确认后，仅删除这个计划。关联任务和实际专注记录保留；历史专注中的原计划 ID 仍保留。存储写入失败时保留编辑内容和原计划，操作者可重试。编辑器打开后切换工作区时，保存和删除会失败，需关闭后在当前工作区重新打开。

计划时长以分钟输入，可输入小数，但不得少于 1 秒。日期、时间按设备本地时区输入，存储为固定时间点；设备时区变化会改变本地显示，不会把已保存计划改为新时区中的同一钟点。

## Android 本机提醒

“设置 → 任务提醒”提供两个互相独立、默认开启的本机开关：

| 开关 | 触发条件和显示内容 |
| --- | --- |
| 任务温馨提醒 | 当前工作区有状态为 `open` 的任务时，显示一条静默持续通知，内容只有待办数量 |
| 截止与计划开始提醒 | 未完成任务到达 `due_at`，或状态为 `scheduled` 的计划到达 `starts_at` 时，显示一条可清除的通用通知 |

独立日程也会产生计划开始提醒。关联任务完成、取消或删除后，不再安排该任务的截止提醒和关联计划提醒。计划完成、取消或删除后，不再安排该计划的开始提醒。取消关联后，独立日程继续按自己的开始时间提醒。

任务编辑器中的截止日期包含具体时间。只选择日期而未修改时间时，时间为 `00:00`；需要日间提醒时，应同时选择截止时间。截止提醒在截止时间触发，当前没有提前若干分钟的配置。

两个开关只影响当前设备，退出账户和切换工作区不会重置开关。开关不随同步、工作区备份或工作区复制转移。Android 原生只保存当前工作区标识、事件 ID、时间、提醒类型和已处理记录，不保存任务标题、备注或项目名，也不自行连接服务器。

通知需要系统允许应用通知以及对应的通知分类。Android 13 及以上需要通知权限；自动权限申请至多提示一次，拒绝后可使用“检查 / 申请通知权限”主动申请。系统分类分别为“任务温馨提醒”和“截止与计划提醒”。“定时提醒分类设置”可打开后者。关闭一个分类不影响另一个分类。通知不可用时，本地任务和计划仍可保存。

## 触发时间、恢复和限制

定时提醒使用 `AlarmManager.setAndAllowWhileIdle`，只向系统登记最近一个待触发时间。触发后合并已经到时的事件为一条通知，并登记下一次时间；当前不申请精确闹钟权限，不使用后台轮询。Android 可能批量处理或延迟非精确闹钟，节电模式、系统后台限制和厂商策略也可能影响通知时间。该功能不适用于要求严格准点的闹钟用途。[Android 官方闹钟说明](https://developer.android.com/develop/background-work/services/alarms)

每个事件的同一时间点只处理一次。首次启用、载入旧任务或把时间改到过去时，不补发这些新载入的过期事件。此前已登记但尚未处理的事件可在系统延迟触发或重启恢复时合并提醒；事件到时若通知权限或分类被关闭，会记录为已处理，之后授权不会补发。

设备启动、应用覆盖更新、系统时间和时区变化后，接收器按本机快照重建最近一次提醒。客户端保存任务或计划、完成任务、同步取得新数据及切换工作区后，会更新该快照；旧工作区提醒会取消。客户端没有同步的新数据不会影响本机闹钟。

系统强行停止应用后，需重新打开应用才能恢复。卸载或清除数据会删除本机提醒设置和快照。通知栏仅保留最新的一条定时提醒，点击后进入任务页；通知正文不包含对应任务名称。

## 验证范围

自动化检查覆盖计划 ID 保留、重新关联、删除后任务与历史记录保留、写入失败，以及定时提醒的事件过滤、时间变化、完成与删除取消、本机开关持久化和平台失败重试。Android 系统的实际触发时间、重启广播、通知权限、厂商节电策略和通知展示应以对应最终 APK 的设备验收记录为准。2026-10-17 的实现记录未包含真机测试或 Release 发布；各版本结果见对应 Release 说明。
