# Android 默认排序与任务提醒真机检查

更新日期：2026-10-11。适用当前源码 `0.3.0-preview.1+6`。本清单记录待执行步骤，不是已通过的真机报告；正式发行应在最终签名候选上重新检查。

## 准备与记录

使用可丢弃的本地工作区和演示任务，不使用唯一持有个人数据的设备进行清除数据、卸载或故障测试。至少分别覆盖 Android 8–12 和 Android 13 及以上；划掉持续通知的规则还应覆盖 Android 14 及以上。系统通知授权、重启、强行停止和安装更新由设备操作者执行。

每次记录源码提交或快照标识、APK SHA-256、签名证书指纹、设备型号、Android 版本、系统通知权限与分类状态、操作结果和异常。窗口截图使用演示数据，注意遮挡通知栏中其他应用的私人内容。

2026-10-11，对合并后的 `0.3.0-preview.1+6` 源码执行 Flutter 静态分析、188 项 Flutter 测试和 debug APK 构建，均通过。这些结果不证明以下真机项目已经通过，也不证明正式 release 构建或发布完成。

## 默认排序

1. 在任务页按“无、低、中、高、紧急”的创建顺序各建一项任务。列表应显示“紧急、高、中、低、无”；同优先级保留 `rank` 顺序，相同 `rank` 时按任务 ID 排列。修改其中一项优先级，确认立即重新排列；退出进程后再打开，排序应继续生效。
2. 分别检查收集箱、项目、标签、搜索结果及已完成列表，再检查日历和专注的任务选择器。它们应沿用通用任务列表顺序，不改任务正文、截止时间或排期。
3. 给两项任务安排不同的当天开始时间，在“今日”确认按计划时间排列；未排期任务的上移、下移或拖动应继续有效。提高优先级不能替代计划时间或手动顺序。

## 通知栏任务提醒

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| REM-01 默认与权限 | 打开全新演示安装，先确认空工作区，再创建第一项任务；在需要权限的版本分别执行允许和拒绝 | 开关默认开启；空工作区不显示提醒、不自动申请权限。有待办且允许通知后显示一条静默提醒。拒绝后任务仍能保存，后续数量变化不反复自动弹窗，可在设置中主动申请 |
| REM-02 数量与完成 | 创建第二项任务，再逐项完成；最后重新打开一项已完成任务 | 始终最多一条任务提醒，数量依次更新；完成全部任务后移除，重新有未完成任务时恢复。只计入 `open`，已有 `completed` 或 `cancelled` 测试数据不计入 |
| REM-03 内容与点击 | 查看通知与锁屏，再分别在进程未运行、应用后台和设置页打开时点击通知 | 通知内容为通用温馨提示和数量，不含标题、备注或项目名。点击打开任务页，仍有待办时不因点击自动移除提醒 |
| REM-04 未保存表单 | 修改任务表单而不保存，切到后台后点击任务提醒 | 原表单退出确认仍生效；取消退出保留输入，确认放弃后可回到任务页，不直接丢弃草稿 |
| REM-05 开关与重启 | 在“设置 → 任务提醒”关闭开关，退出并重开应用；再次开启 | 关闭立即移除，重开仍关闭；再次开启且系统允许时恢复。设置写入失败时保留原开关并显示可重试提示 |
| REM-06 系统分类 | 分别关闭系统应用通知和“任务温馨提醒”分类，再返回应用；恢复系统授权后再返回 | 设置页反映实际受限状态，不把开启开关当作授权。应用通知允许但分类关闭时不展示；恢复并返回前台后重新检查。专注通知分类不与任务提醒混为同一分类 |
| REM-07 工作区与备份 | 在待办数量不同的两个演示工作区间切换，再恢复或复制演示备份 | 先取消旧提醒，按新工作区数量展示；空工作区不保留旧数量。恢复和复制保留原工作区，不连接服务器，使用当前设备的提醒开关；备份不携带新提醒开关或原生快照 |
| REM-08 系统划掉 | 在系统允许划掉持续通知的设备上移除提醒，再改变待办数量或回到前台 | 同一条提醒重新展示。只改标题或优先级而数量不变不保证立即恢复；需要持续关闭时应关闭提醒开关或系统分类 |
| REM-09 进程与设备 | 在有待办时退出进程、重启设备并解锁，再执行系统强行停止和重新打开应用 | 已显示通知的存留及启动广播恢复分别记录。重启读取最近保存的数量快照；强行停止后需重新打开应用恢复，不声称停止期间持续运行或拉取服务器 |
| REM-10 升级与同步 | 用同包名、同证书且更高构建号的受控候选更新；应用关闭期间在另一测试设备更改任务，再打开本机同步 | 更新后按本机快照恢复，已保存关闭选择保留；本机同步后使用新数量。提醒自身不连接服务器，也不提供截止时间或日历时段定时触发 |

REM-05 的真实存储故障只在可丢弃环境执行；没有安全且可复现的故障条件时标为未验证，不以自动化失败测试代替设备结果。REM-10 需要更高构建号的候选；相同构建号的两个 APK 不能作为该项更新验收依据。

## 判定与失败处理

每项记录“通过、失败、未验证”和证据；未验证项保持未完成。通知缺失时先核对工作区数量、提醒开关、应用通知权限、通知分类和是否被强行停止。平台更新失败在设置页重试，本地任务保存成功后不要重复创建任务来处理通知故障。

机型的通知显示、锁屏、启动广播和后台限制分别记录；一台设备通过不能作为所有 Android 版本兼容的结论。产品操作见[入门指南](GETTING_STARTED.md#任务温馨提醒)，正式包条件见[发行流程](RELEASING.md#android-预览-apk)。
