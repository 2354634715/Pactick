# 0.3.0-preview.1 发布验证记录

验证日期：2026-10-11。Android 版本为 `0.3.0-preview.1+6`，包名为 `com.example.pactick`。本版将 Windows/Linux x86-64 服务端管理程序、部署脚本和 Android 最新改动作为同一预览发行分发。

最终源码提交、标签和文件哈希由 Release 附件 `RELEASE_SOURCE.json`、`SOURCE_COMMIT.txt`、`SOURCE_MANIFEST.json` 与 `SHA256SUMS.txt` 记录。服务器包另提供 `SERVER_PACKAGE.json` 和 `SERVER_MANIFEST.json`；不能用旧版 APK 或历史部署结果替代本次制品来源。

## 合入范围

- 本机浏览器管理 GUI：部署、API 启停、运行配置、日志、Docker 手工备份及账户创建。
- 本机 `admin create-account`：stdin JSON 输入，复用账户校验和 Argon2id，不签发令牌或登记设备，不依赖公开注册开关。
- Windows/Linux 打包脚本、启动脚本及 Docker Compose 配置，服务器包包含预编译程序与源码。
- Android 主工作区的任务提醒、通知权限入口、通用任务优先级排序，以及历史双设备工作区中的默认专注策略与认证恢复修复。

根目录 `README.md` 保持不变。客户端 README 保留维护者的功能说明，仅将版本事实更新为本版。

## 浏览器与运行验证

Windows 本机管理程序经 Playwright 实际执行以下操作：

1. 选择本机模式，保存隔离 PostgreSQL 连接和测试端口。
2. 点击部署，执行首次迁移并启动 API，`/readyz` 返回成功。
3. 通过表单创建随机密码账户，使用实际 API 验证登录成功，同时确认公开注册仍返回 403。
4. 隐藏生成的密码，检查桌面与 390 像素宽窗口；页面刷新后管理会话仍有效，生成密码不再显示。

截图与完整本机日志保存在忽略的 `output/` 中，不进入仓库或发行源码。截图使用演示邮箱，不包含正式密码、密钥或个人数据。

WSL Debian 的 Linux x86-64 管理程序在 Docker 29.8.2、Compose 5.6.0 中完成真实部署验证：首次构建与拉取镜像、PostgreSQL 就绪、显式迁移、API 就绪、随机密码建号、重复邮箱拒绝、生成密码登录、公开注册仍返回 403、容器日志、`pg_dump -Fc` 备份与 SHA-256 核对，以及停止 API 保留数据库后重新启动。没有执行备份恢复。本次独立项目、测试卷及测试镜像在结束后定向清理，未操作已有部署。

Docker Compose 另通过配置解析，Linux 部署与桌面启动脚本通过 Bash 语法检查。Windows 前台脚本及 Linux 字面环境解析已单独检查。服务器跨平台构建和最终归档由 `package_server.py` 在同一验证快照中执行，构建参数与目标架构记录在包元数据中。

## Windows 构建告警核对

本轮使用 `-ldflags=-s -w` 构建 Windows `healthcheck` 时，卡巴斯基对 Go 临时链接文件报告 `VHO:Trojan-Downloader.Win32.Agent.gen`，构建因访问被拒绝停止。该临时文件未分发，未关闭防护、添加排除或允许被拦截文件。

当前 `healthcheck` 源码仅在 2 秒时限内读取健康检查 URL，默认地址为本机 `/readyz`，最多丢弃 4 KiB 响应；没有下载执行、子进程或文件写入逻辑。Windows 打包改为保留 Go 调试信息，Linux 继续精简符号，两者都使用 `-trimpath`。这些源码和参数核对不能单独证明原告警是误报。

本机卡巴斯基 21.22 的仅报告扫描对 Go 编译器、GUI/API/迁移验证程序，以及非精简 Windows x86-64 测试包分别报告 0 检出、0 可疑、0 跳过、0 错误。测试包扫描处理 305 个对象。此结果只适用于当时的候选和检测库；最终发行包在上传前另行扫描，并将结果与其 SHA-256 绑定。扫描无检出不构成安全保证。
