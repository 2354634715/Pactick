# Feedback and contribution rules

This project accepts bug reports, feature suggestions, and documentation issues through GitHub Issues. External code, documentation, and test changes are not currently accepted. The maintainer is responsible for changes and releases in the project repository.

## Open an issue

Search existing issues before submitting to avoid duplicate reports.

- Bug reports should include the version, environment, reproduction steps, expected behavior, and actual behavior. If reproduction is unreliable, describe the conditions and frequency.
- Feature suggestions should describe the use case, current problem, and expected behavior.
- Documentation reports should identify the file or page and the inaccurate, missing, or unusable instructions.

Use demonstration data in logs and screenshots, or remove sensitive information first. Do not post keys, tokens, real account data, database backups, signing files, or private server information in public issues. Use the [private reporting process](SECURITY.en.md) for security issues.

The maintainer prioritizes data loss and security, followed by core functionality defects, usability improvements, and new features. Maintenance depends on available time. No fixed response time or acceptance of every suggestion is promised.

## Pull requests and repository write access

Describe problems and suggestions through issues; do not submit pull requests (PRs). External PRs will be closed without merging, including code fixes, documentation changes, and additional tests.

External reporters are not granted repository write access. A public repository still allows users to fork and open PRs. This document defines how the maintainer handles those requests; it does not disable GitHub features. Submitting a PR does not automatically change the project repository. A change enters the repository only when the maintainer merges it.
