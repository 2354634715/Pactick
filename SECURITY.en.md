# Reporting security issues

Report issues through GitHub Issues or the maintainer's email. Public issues may describe symptoms, affected versions, and impact. Send material containing exploitable vulnerability details, tokens, databases, personal tasks, or server secrets privately by email.

## Reporting channels

- General issues: [GitHub Issues](https://github.com/2354634715/Pactick/issues).
- Private security reports: [w66610@outlook.com](mailto:w66610@outlook.com).

The maintainer selected these addresses on 2026-10-02. GitHub accessibility and receipt of a test email have not yet been verified; verify them before public distribution. If submission is unavailable, contact the distributor who provided the test package. Do not submit exploitable vulnerability details or sensitive data in public issues.

The official repository may also enable GitHub Private vulnerability reporting. Once enabled, reporters can submit privately through Security → Advisories → Report a vulnerability. This is optional configuration; see the [official GitHub documentation](https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/configuring-private-vulnerability-reporting-for-a-repository).

## Information to include

- Affected version and Android or server environment.
- Reproduction steps using a demonstration account and the minimum necessary data.
- Expected behavior, actual behavior, and impact.
- Any proposed fix and a way to contact you privately.

There is currently no public stable version or committed security maintenance period. The maintainer handles reports according to their impact and available time. Self-hosters are responsible for server updates, TLS, backups, and key management. If a key is exposed, rotate the credentials in the affected systems first.
